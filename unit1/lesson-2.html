01

จุดประสงค์การเรียนรู้

หลังเรียนครั้งนี้ ผู้เรียนสามารถ…

  1. อธิบายรูปแบบการทำงานแบบ Client–Server ได้
  2. อธิบายหน้าที่ของ IP Address และระบบ DNS ได้
  3. เรียงลำดับขั้นตอนการทำงานของเว็บ ตั้งแต่พิมพ์ URL จนแสดงผลได้
  4. อ่านส่วนประกอบของ HTTP Request/Response และความหมายของ Status Code ได้
  5. บอกความแตกต่างระหว่าง HTTP และ HTTPS และเหตุผลที่ควรใช้ HTTPS ได้
  6. ใช้ DevTools และคำสั่ง nslookup / ping ตรวจสอบการทำงานของเว็บได้
02

Client–Server: ผู้ขอ กับ ผู้ให้บริการ

เว็บทั้งโลกทำงานด้วยรูปแบบ “ขอ → ตอบ”

Client (ไคลเอนต์) = ผู้ขอ

อุปกรณ์และโปรแกรมฝั่งผู้ใช้ ได้แก่ คอมพิวเตอร์ มือถือ + เว็บเบราว์เซอร์ ทำหน้าที่ ส่งคำขอ (Request) และ แสดงผล หน้าเว็บที่ได้รับ

Server (เซิร์ฟเวอร์) = ผู้ให้บริการ

คอมพิวเตอร์ที่เปิดตลอด 24 ชม. ติดตั้ง โปรแกรมเว็บเซิร์ฟเวอร์ (Apache, Nginx) เก็บไฟล์เว็บไซต์ ทำหน้าที่ รับคำขอ ประมวลผล และส่งคำตอบ (Response)

เปรียบเทียบกับการสั่งอาหารในร้าน 🍜

03

IP Address & DNS: สมุดโทรศัพท์ของอินเทอร์เน็ต

คนจำชื่อ — คอมพิวเตอร์จำตัวเลข

คอมพิวเตอร์ทุกเครื่องบนอินเทอร์เน็ตต้องมี IP Address เช่น 203.0.113.10 (IPv4 มี 4 ชุด ชุดละ 0–255) แต่คนจำตัวเลขยาก จึงมี DNS (Domain Name System) ทำหน้าที่ แปลงชื่อโดเมนเป็น IP Address เหมือน “สมุดรายชื่อ” ในโทรศัพท์ที่เรากดชื่อ “แม่” แล้วเครื่องโทรออกเป็นเบอร์ให้เอง

DNS ไม่ได้มีเครื่องเดียว แต่เป็น ระบบลำดับชั้น ทั่วโลก ดูแอนิเมชันว่าการถามหา IP เดินทางอย่างไร 👇

ลองเองได้!เปิด Command Prompt แล้วพิมพ์ nslookup www.google.com จะเห็น IP ที่ DNS ตอบกลับมา (ทำในใบงาน 1.2)

ทำไมต้องรู้เรื่องนี้?เวลาเว็บ “ไม่ขึ้น” นักพัฒนาต้องไล่ได้ว่าพังที่ขั้นไหน — DNS หาไม่เจอ (ชื่อผิด/โดเมนหมดอายุ)? เชื่อมต่อเซิร์ฟเวอร์ไม่ได้ (เซิร์ฟเวอร์ล่ม)? ได้ 404 (ไฟล์ไม่มี)? หรือ 500 (โปรแกรมฝั่งเซิร์ฟเวอร์ผิด)?

05

HTTP Request & Response

“จดหมาย” ที่เบราว์เซอร์กับเซิร์ฟเวอร์ส่งหากัน หน้าตาเป็นแบบนี้จริง ๆ

HTTP Method ที่ใช้บ่อย

Methodความหมายตัวอย่างในชีวิตจริง
GETขอดู/ดึงข้อมูล (ข้อมูลอาจอยู่ใน URL)เปิดหน้าข่าว, ค้นหาใน Google
POSTส่งข้อมูลใหม่ไปให้เซิร์ฟเวอร์ (อยู่ใน Body)ล็อกอิน, สมัครสมาชิก, ส่งฟอร์ม
PUT / PATCHแก้ไขข้อมูลที่มีอยู่แก้ไขโปรไฟล์
DELETEลบข้อมูลลบโพสต์, ลบสินค้าจากตะกร้า
06

HTTP Status Code: เซิร์ฟเวอร์ตอบว่าอะไร?

ตัวเลข 3 หลัก หลักแรกบอกกลุ่ม · แตะการ์ดเพื่อพลิก

กลุ่มความหมายจำง่าย ๆ
1xxInformational — ข้อมูลระหว่างทำงาน“รับทราบ กำลังดำเนินการ”
2xxSuccess — สำเร็จ“ได้เลย นี่ครับ” ✅
3xxRedirection — ย้ายที่/ให้ไปที่อื่น“ร้านย้ายไปซอยข้าง ๆ” ↪️
4xxClient Error — ฝั่งผู้ขอผิด“คุณขอผิดเอง” 🙅
5xxServer Error — ฝั่งเซิร์ฟเวอร์ผิดพลาด“ครัวไฟไหม้” 🔥
07

HTTP vs HTTPS: ทำไมต้องมีกุญแจ 🔒

ดูว่าแฮกเกอร์ที่ดักฟัง Wi-Fi สาธารณะเห็นอะไรบ้าง

HTTP

  • พอร์ต 80
  • ไม่เข้ารหัส อ่านได้ระหว่างทาง
  • เบราว์เซอร์ขึ้นเตือน “ไม่ปลอดภัย”
  • อันดับใน Google ต่ำกว่า
VS

HTTPS

  • พอร์ต 443
  • เข้ารหัสด้วย TLS + มีใบรับรอง
  • มีรูปกุญแจ 🔒 ที่แถบที่อยู่
  • มาตรฐานของเว็บทุกวันนี้ (มีใบรับรองฟรี เช่น Let's Encrypt)

09

แบบทดสอบท้ายครั้งที่ 2

เลือกคำตอบเดียว

หน้าที่หลักของ DNS คือข้อใด

DNS = สมุดรายชื่อของอินเทอร์เน็ต แปลงชื่อที่คนจำง่ายเป็นเลข IP ที่คอมพิวเตอร์ใช้

เรียงลำดับให้ถูก: (ก) ส่ง HTTP Request (ข) ถาม DNS หา IP (ค) Render หน้าเว็บ (ง) ได้ Response 200 OK

ต้องรู้ IP ก่อน (DNS) → จึงส่ง Request ไปหาเซิร์ฟเวอร์ได้ → ได้ Response → เบราว์เซอร์จึงวาดหน้าเว็บ

นักเรียนพิมพ์ชื่อไฟล์ใน URL ผิด เซิร์ฟเวอร์จะตอบรหัสสถานะใด

404 Not Found = ไม่พบไฟล์ที่ขอ เป็นความผิดพลาดฝั่งผู้ขอ (4xx)

การกรอกฟอร์มสมัครสมาชิกแล้วกดส่ง ควรใช้ HTTP Method ใด

POST ใช้ส่งข้อมูลใหม่ไปยังเซิร์ฟเวอร์ ข้อมูลอยู่ใน Body ไม่แสดงใน URL

ข้อใดเป็นจุดเด่นของ HTTPS เมื่อเทียบกับ HTTP

HTTPS ใช้ TLS เข้ารหัสข้อมูล และมีใบรับรองยืนยันว่าเป็นเว็บจริง ใช้พอร์ต 443

รหัสสถานะ 500 Internal Server Error บอกอะไรกับนักพัฒนา

5xx = ฝั่งเซิร์ฟเวอร์ผิด เช่น โค้ด PHP มีบั๊ก หรือเชื่อมฐานข้อมูลไม่ได้

10

สรุปครั้งที่ 2

ภาพใหญ่ในประโยคเดียว: “ถามที่อยู่ → เคาะประตู → ขอของ → ได้ของ → ประกอบร่าง”

  • เว็บทำงานแบบ Client–Server: เบราว์เซอร์ส่ง Request → เซิร์ฟเวอร์ส่ง Response
  • DNS แปลงชื่อโดเมน → IP โดยถามต่อเป็นทอด ๆ Root → TLD → Name Server และจำไว้ใน Cache
  • ลำดับหลัก: DNS → TCP/TLS → HTTP Request → ประมวลผล → HTTP Response → โหลดไฟล์ประกอบ → Render
  • ข้อความ HTTP มี Start line + Headers + Body · Method หลัก: GET, POST, PUT, DELETE
  • Status Code: 2xx สำเร็จ · 3xx ย้ายที่ · 4xx ผู้ขอผิด · 5xx เซิร์ฟเวอร์ผิด
  • HTTPS = HTTP + การเข้ารหัส TLS + ใบรับรอง → ต้องใช้กับทุกเว็บ

คำถามชวนคิดสำหรับครั้งหน้าResponse ที่ส่งกลับมามี HTML, CSS, JS — สามอย่างนี้ทำหน้าที่ต่างกันอย่างไร? และทำไมบางเว็บแสดงข้อมูลไม่เหมือนกันในแต่ละคน (เช่น หน้าผลการเรียน)?
