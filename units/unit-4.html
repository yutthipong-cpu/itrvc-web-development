01

CSS คืออะไร & ใส่ได้ 3 วิธี

CSS (Cascading Style Sheets) = ภาษากำหนดหน้าตา

h1 { color: #6d28d9; font-size: 2rem; }

Selector (เลือกอะไร) · Property (เปลี่ยนอะไร) · Value (เป็นค่าอะไร) · ; จบคำสั่ง · { } = Declaration block

1. Inline

<p style="color:red">

ใส่ในแท็ก — แก้ยาก ใช้ซ้ำไม่ได้ ❌

2. Internal

<style> p { color: red; } </style>

ใน <head> ของหน้านั้น — ใช้ได้หน้าเดียว

3. External ✓

<link rel="stylesheet" href="css/style.css">

ไฟล์แยก ใช้ทุกหน้า แก้ที่เดียวเปลี่ยนทั้งเว็บ

ไฟล์ CSS ภายนอกถูก เบราว์เซอร์ Cache ไว้ — เปิดหน้าที่ 2, 3, 4 ไม่ต้องโหลดซ้ำ เว็บจึงเร็วขึ้น · ถ้าแก้ CSS แล้วบนเซิร์ฟเวอร์ไม่เปลี่ยน ให้กด Ctrl+F5 หรือต่อท้ายไฟล์ style.css?v=2 (Cache busting)

03

Cascade & Specificity: กฎไหนชนะ?

“ทำไมสั่งสีแดงแล้วไม่แดง!?” — คำตอบอยู่ที่นี่

ลำดับการตัดสิน (Cascade)

  1. ความสำคัญ — !important ชนะทุกอย่าง (ใช้เป็นทางสุดท้ายเท่านั้น)
  2. Specificity (ความเฉพาะเจาะจง) — คิดคะแนนเป็น (ID, Class, Tag) เทียบจากหลักซ้ายก่อน · Inline style ชนะ selector ทุกแบบ
  3. ลำดับในไฟล์ — คะแนนเท่ากัน ตัวที่เขียน ทีหลัง ชนะ

แล็บ: คำนวณ Specificity

สมมติ Selector A ตั้งสีน้ำเงิน และ B ตั้งสีชมพู กับลิงก์เดียวกัน — พิมพ์ Selector เองหรือกดตัวอย่าง

A
B
ลิงก์ตัวอย่าง →

Inheritance (การสืบทอด): คุณสมบัติด้านตัวอักษร (color, font-family, line-height) ส่งต่อจาก parent ไป child อัตโนมัติ — จึงตั้งฟอนต์ที่ body ครั้งเดียวทั้งเว็บ · แต่ margin, padding, border ไม่สืบทอด

ติด !important แก้ปัญหาไปทีละจุด = สร้างปัญหาใหม่ (ต้องใช้ !important ซ้อนไปเรื่อย ๆ) · ให้แก้ด้วยการลด/เพิ่ม Specificity ให้เหมาะสมแทน

<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>

  font-family: 'Sarabun', system-ui, sans-serif;  /* สำรองถ้าโหลดไม่ได้ */

  color: #1f2937;
}
h1, h2, h3 { font-family: 'Prompt', sans-serif; line-height: 1.3; }
.lead { max-width: 65ch; }  /* จำกัดความยาวบรรทัด */

display=swap ทำให้เบราว์เซอร์แสดงข้อความด้วยฟอนต์สำรองไปก่อน แล้วค่อยสลับเมื่อฟอนต์โหลดเสร็จ → ไม่มีช่วง “ข้อความหายไป” (FOIT) · preconnect เปิดการเชื่อมต่อไปเซิร์ฟเวอร์ฟอนต์ล่วงหน้า ประหยัดเวลา DNS+TLS

โหลดเฉพาะน้ำหนักที่ใช้จริง (เช่น 400 กับ 700) — ฟอนต์ไทยแต่ละน้ำหนักมีขนาดไฟล์ใหญ่กว่าฟอนต์อังกฤษ

06

Box Model: ทุกอย่างคือกล่อง

เข้าใจเรื่องนี้ = แก้ปัญหา “ทำไมกล่องล้น/ไม่ตรง” ได้ 80%

บรรทัดแรกของ style.css ทุกโปรเจกต์ (CSS Reset ฉบับย่อ)
*, *::before, *::after { box-sizing: border-box; }
body { margin: 0; }
img { max-width: 100%; height: auto; display: block; }
.container { max-width: 1100px; margin: 0 auto; padding: 0 16px; }  /* จัดกลาง */

Margin collapse: margin บน-ล่างของกล่องที่อยู่ติดกันจะ “ยุบรวม” เหลือค่าที่มากกว่า (ไม่บวกกัน) เช่น 20px + 30px = 30px — เป็นพฤติกรรมตั้งใจของ CSS ที่มือใหม่งงกันทั่วโลก

ทางลัด: margin: 10px 20px = บน-ล่าง 10 ซ้าย-ขวา 20 · margin: 1px 2px 3px 4px = บน ขวา ล่าง ซ้าย (หมุนตามเข็มนาฬิกา “TRouBLe”)

07

display & position

กล่องวางตัวอย่างไร และจะ “ลอย” ออกจากลำดับปกติได้อย่างไร

displayพฤติกรรม
blockกว้างเต็มแถว ขึ้นบรรทัดใหม่ (div, p, h1)
inlineอยู่ในบรรทัด ตั้ง width/height ไม่ได้ (a, span, b)
inline-blockอยู่ในบรรทัด แต่ตั้งขนาดได้ (ปุ่ม)
flex / gridจัดลูกด้านใน (หัวข้อถัดไป)
noneซ่อน (ไม่กินพื้นที่)
positionใช้ทำ
staticค่าปกติ ตามลำดับ HTML
relativeขยับจากที่เดิม · เป็น “จุดอ้างอิง” ให้ลูก absolute
absoluteลอยวางตามพ่อที่เป็น relative · ป้าย “SALE” บนการ์ด
fixedติดจอแม้เลื่อน · ปุ่มแชต/ปุ่มขึ้นบนสุด
stickyเลื่อนปกติจนถึงขอบแล้วติด · เมนูติดด้านบน
เมนูติดด้านบนเมื่อเลื่อน (1 บรรทัดที่สำคัญ)
.site-header { position: sticky; top: 0; z-index: 100; background: white; }

z-index (ใครอยู่บน) ทำงานกับองค์ประกอบที่มี position ไม่ใช่ static (หรือเป็นลูกของ flex/grid) — ถ้าตั้ง z-index แล้วไม่มีผล ให้ตรวจ position ก่อน และระวัง “stacking context” ของกล่องแม่ที่ครอบอยู่

Mobile-first Media Query


/* 1) มือถือ (ค่าพื้นฐาน ไม่ต้องอยู่ใน @media) */
.menu-list { display: grid; grid-template-columns: 1fr; gap: 12px; }
.nav-links { display: none; }        /* ใช้ปุ่ม ☰ แทน */

/* 2) แท็บเล็ตขึ้นไป */
@media (min-width: 768px) {
  .menu-list { grid-template-columns: 1fr 1fr; }
}

/* 3) จอคอมพิวเตอร์ */
@media (min-width: 992px) {
  .menu-list { grid-template-columns: repeat(3, 1fr) 260px; }
  .nav-links { display: flex; }
  .burger { display: none; }
}

        

          
ทดสอบใน DevTools: กด Ctrl+Shift+M (Device toolbar) เลือกรุ่นมือถือ หรือลากขอบ · แต่ ต้องทดสอบบนมือถือจริงด้วย เพราะนิ้วกดไม่แม่นเท่าเมาส์

          
แล็บด้านบนใช้ Container Query (@container) ซึ่งตอบสนองต่อขนาด “กล่องแม่” แทนขนาดจอ — CSS สมัยใหม่ที่ทำให้คอมโพเนนต์ปรับตัวเองได้ไม่ว่าจะถูกวางไว้ตรงไหน

          
ลืม <meta name="viewport"> = Media query บนมือถือจริงไม่ทำงาน (แต่ใน DevTools อาจดูเหมือนปกติ) — ตรวจทุกหน้า!

@media (prefers-color-scheme: dark) {   /* เปลี่ยนตามการตั้งค่าเครื่องผู้ใช้ */
  :root { --bg: #0f0c15; --text: #f2eef8; }
}
body { background: var(--bg); color: var(--text); }
.btn {
  background: var(--accent); color: white;
  padding: 12px 20px; border-radius: var(--radius);
  transition: transform .2s, box-shadow .2s;
}
.btn:hover { transform: translateY(-2px); box-shadow: 0 8px 20px rgb(0 0 0 / 20%); }
.btn:focus-visible { outline: 3px solid var(--brand); }  /* Accessibility */

        

          
เปลี่ยนธีมทั้งเว็บด้วยการแก้ตัวแปรที่เดียว — เว็บที่คุณกำลังดูอยู่นี้ใช้เทคนิคนี้ทำปุ่ม auto/light/dark มุมขวาบน (ลองกดดู!)

          
แอนิเมชันที่ลื่นที่สุดคือการเปลี่ยน transform และ opacity เพราะทำที่ขั้น Composite ด้วย GPU (หน่วยที่ 1) · ถ้าเปลี่ยน width top margin จะต้อง Layout ใหม่ทุกเฟรม → กระตุก

          
เคารพผู้ใช้ที่เวียนหัวกับการเคลื่อนไหว: @media (prefers-reduced-motion: reduce) { * { animation: none; transition: none; } }

Selector ใดมี Specificity สูงที่สุด
#menu a = (1,0,1) ชนะทุกตัวที่ไม่มี ID

          
ถ้า Specificity เท่ากัน กฎใดชนะ
ลำดับในไฟล์ (Source order) — ตัวหลังชนะ

          
width: 300px; padding: 20px; border: 5px (content-box) กล่องกว้างจริงเท่าไร
300 + 20×2 + 5×2 = 350 · ถ้าใช้ border-box จะได้ 300 พอดี

          
หน่วยใดอิงขนาดฟอนต์ของ <html> (ค่าเริ่มต้น 16px)
1rem = ขนาดฟอนต์ root

          
ต้องการให้กล่องอยู่กึ่งกลางทั้งแนวนอนและแนวตั้งด้วย Flexbox ใช้ข้อใด
จัดทั้งแกนหลักและแกนรอง

          
โค้ด repeat(auto-fit, minmax(200px, 1fr)) ทำอะไร
Responsive โดยไม่ต้องเขียน Media query

          
Mobile-first เขียน Media query ด้วยเงื่อนไขใด
เริ่มจากมือถือ แล้วเพิ่มกฎเมื่อจอกว้าง “อย่างน้อย” เท่าไร
