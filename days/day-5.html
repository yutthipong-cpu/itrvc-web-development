03

ติดตั้ง WordPress

ทางเลือก A ฝึกบน XAMPP (เร็ว) · ทางเลือก B ติดตั้งบนเซิร์ฟเวอร์จริง

  1. XAMPP Start Apache + MySQL → เปิด localhost/phpmyadmin → New → ตั้งชื่อฐานข้อมูล wp_project เลือก Collation utf8mb4_unicode_ci (รองรับภาษาไทยและอีโมจิ) → Create
  2. ดาวน์โหลด WordPress จาก wordpress.org แตกไฟล์ไว้ที่ C:\xampp\htdocs\wp\
  3. เปิด http://localhost/wp → เลือกภาษา ไทย
  4. กรอก Database: ชื่อ wp_project · User root · Password (ว่าง) · Host localhost · Table prefix wp_ → WordPress สร้าง wp-config.php ให้
  5. ตั้งชื่อเว็บ · ชื่อผู้ใช้ห้ามเป็น admin · รหัสผ่านแข็งแรง · อีเมลจริง → ติดตั้ง → เข้า localhost/wp/wp-admin

ต้องมีสิทธิ์ sudo (ครูอาจเตรียมให้แล้ว) · Ubuntu Server 22.04/24.04

1) ติดตั้งแพ็กเกจ (ครั้งเดียวต่อเซิร์ฟเวอร์)
sudo apt update
sudo apt install -y nginx mariadb-server php-fpm php-mysql php-xml php-curl php-gd php-mbstring php-zip php-intl
2) สร้างฐานข้อมูลและผู้ใช้ (sudo mysql)
CREATE DATABASE wp_student01 CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'wp_student01'@'localhost' IDENTIFIED BY 'ตั้งรหัสผ่านยาวๆ';
GRANT ALL PRIVILEGES ON wp_student01.* TO 'wp_student01'@'localhost';
FLUSH PRIVILEGES;
3) ดาวน์โหลด WordPress
cd /var/www
sudo wget https://wordpress.org/latest.tar.gz
sudo tar -xzf latest.tar.gz
sudo mv wordpress wp-student01
sudo chown -R www-data:www-data /var/www/wp-student01

จากนั้นตั้งค่า Nginx ให้รัน PHP (ดูบล็อก WordPress ในหัวข้อ Deploy) แล้วเปิดโดเมนเพื่อติดตั้งต่อเหมือนทางเลือก A

ย้าย WordPress จาก localhost ขึ้นเซิร์ฟเวอร์จริงแบบง่าย: ใช้ปลั๊กอิน All-in-One WP Migration หรือ Duplicator — Export เป็นไฟล์เดียว แล้ว Import ที่ปลายทาง (ระบบแก้ URL ในฐานข้อมูลให้เอง)

05

ความปลอดภัย WordPress

WordPress ถูกโจมตีบ่อยเพราะใช้กันมาก — แต่ป้องกันได้ถ้าทำตามนี้

  • อัปเดต Core / ธีม / ปลั๊กอินสม่ำเสมอ (สาเหตุถูกแฮกอันดับ 1 คือปลั๊กอินเก่า)
  • ห้ามใช้ชื่อผู้ใช้ admin · รหัสผ่านยาว · เปิด 2FA
  • ลบธีม/ปลั๊กอินที่ไม่ใช้
  • สำรองข้อมูลอัตโนมัติ (ไฟล์ + ฐานข้อมูล)
  • ใช้ HTTPS ทั้งเว็บ
  • สิทธิ์ไฟล์ถูกต้อง wp-config.php ไม่ให้คนอื่นอ่าน
  • จำกัดการล็อกอินผิดซ้ำ ๆ (Brute force)
  • ปิดการแก้ไขไฟล์จากหน้าแอดมิน: define('DISALLOW_FILE_EDIT', true);

ห้ามใช้ธีม/ปลั๊กอิน “เถื่อน” (Nulled) ที่แจกฟรีจากเว็บไม่เป็นทางการ — มักฝังมัลแวร์/ลิงก์สแปมไว้ ผิดลิขสิทธิ์ และอาจทำให้เซิร์ฟเวอร์ทั้งเครื่องถูกยึด

ประเภทของเว็บโฮสติ้ง

เลือกตามงบ ความรู้ และความต้องการควบคุม

ประเภทเปรียบเหมือนข้อดีข้อควรรู้
Shared Hostingหอพักถูก มี cPanel/DirectAdmin ใช้ง่ายแชร์ทรัพยากร ปรับแต่งเซิร์ฟเวอร์ไม่ได้
VPS (Virtual Private Server)คอนโดของตัวเองได้สิทธิ์ root ติดตั้งอะไรก็ได้ (คอร์สนี้ใช้)ต้องดูแลความปลอดภัยเอง
Cloud (AWS, GCP, Azure)โรงแรมที่ขยายห้องได้ทันทีขยายตามโหลด จ่ายตามใช้คิดค่าบริการซับซ้อน
Dedicated / On-premiseบ้านทั้งหลังทรัพยากรเต็มเครื่อง (เซิร์ฟเวอร์ของวิทยาลัย)ดูแลฮาร์ดแวร์ ไฟ เน็ตเอง
Static hosting (GitHub Pages, Netlify, Cloudflare Pages)ป้ายประกาศฟรี เร็ว มี HTTPSใช้ได้เฉพาะ HTML/CSS/JS (ไม่มี PHP)
08

โดเมน & DNS: ชี้ชื่อมาที่เซิร์ฟเวอร์ของเรา

จากการจดโดเมน → จนผู้ใช้ทั่วโลกพิมพ์ชื่อแล้วมาถึงเครื่องเรา

ตรวจว่า DNS ชี้ถูกแล้วหรือยัง
nslookup student01.example.ac.th
nslookup student01.example.ac.th 1.1.1.1     # ถาม Cloudflare ตรง ๆ (ข้าม cache ของ ISP)
ping student01.example.ac.th

Wildcard record *.example.ac.th A 203.0.113.50 ทำให้ ทุกซับโดเมน ชี้มาที่เซิร์ฟเวอร์อัตโนมัติ — ครูสร้างครั้งเดียว นักเรียน 40 คนไม่ต้องรอเพิ่ม record ทีละคน

ตรวจดูว่า DNS กระจายไปทั่วโลกหรือยังได้ที่เว็บ dnschecker.org — จะเห็นแผนที่โลกพร้อมผลการ resolve จากแต่ละประเทศ

โดเมนหมดอายุ = เว็บหายทั้งเว็บ (และอีเมลด้วย) แม้เซิร์ฟเวอร์ยังทำงานปกติ — หลายองค์กรเสียโดเมนให้คนอื่นเพราะลืมต่ออายุ

Linux & SSH: เข้าไปบัญชาการเซิร์ฟเวอร์

เซิร์ฟเวอร์ส่วนใหญ่ไม่มีหน้าจอ — เราสั่งงานผ่านบรรทัดคำสั่งจากระยะไกลอย่างปลอดภัยด้วย SSH

เชื่อมต่อด้วย SSH Key (ปลอดภัยกว่ารหัสผ่าน)
# บนเครื่องเรา (Windows PowerShell / macOS / Linux) — ทำครั้งเดียว
ssh-keygen -t ed25519 -C "student01"

สิทธิ์ (permission)ความหมายใช้กับ
755 (rwxr-xr-x)เจ้าของ อ่าน/เขียน/เข้า · คนอื่น อ่าน/เข้าโฟลเดอร์
644 (rw-r--r--)เจ้าของ อ่าน/เขียน · คนอื่น อ่านอย่างเดียวไฟล์ html css js รูป
600เจ้าของเท่านั้นไฟล์ลับ เช่น private key
777 ❌ทุกคนแก้ได้ห้ามใช้ — เปิดประตูให้แฮกเกอร์

ตัวเลขสิทธิ์มาจากการบวก: r = 4 (อ่าน) · w = 2 (เขียน) · x = 1 (รัน/เข้าโฟลเดอร์) แยก 3 กลุ่ม เจ้าของ–กลุ่ม–คนอื่น → 7 = 4+2+1 · 5 = 4+1 · 6 = 4+2

Deploy: นำเว็บขึ้นเซิร์ฟเวอร์จริง

อัปโหลดไฟล์ → ตั้งสิทธิ์ → ตั้งค่า Nginx → เปิดใช้

  1. เปิด FileZilla → File → Site Manager → New site
  2. Protocol: SFTP – SSH File Transfer Protocol · Host: 203.0.113.50 · Port: 22
  3. Logon Type: Key file (เลือกไฟล์ private key) หรือ Normal ถ้าครูให้รหัสผ่าน · User: student01
  4. ฝั่งขวา (Remote) ไปที่ /var/www/student01 → ลากไฟล์จากฝั่งซ้ายไปวาง
# ครั้งแรก: สร้างโฟลเดอร์บนเซิร์ฟเวอร์ (ถ้ามีสิทธิ์ sudo)
ssh student01@203.0.113.50 "sudo mkdir -p /var/www/student01 && sudo chown student01:www-data /var/www/student01"

# อัปโหลดทั้งโฟลเดอร์ (รันบนเครื่องเรา ในโฟลเดอร์โครงงาน)
scp -r ./* student01@203.0.113.50:/var/www/student01/

# หรือ rsync: ส่งเฉพาะไฟล์ที่เปลี่ยน (เร็วกว่ามากเมื่ออัปเดตครั้งต่อไป)
rsync -avz --delete ./ student01@203.0.113.50:/var/www/student01/

# ตั้งสิทธิ์บนเซิร์ฟเวอร์
find /var/www/student01 -type d -exec chmod 755 {} \;
find /var/www/student01 -type f -exec chmod 644 {} \;

มืออาชีพนิยมเก็บโค้ดใน Git แล้วดึงลงเซิร์ฟเวอร์ — มีประวัติทุกเวอร์ชัน ย้อนกลับได้

# บนเครื่องเรา
git add . && git commit -m "เพิ่มหน้าติดต่อ" && git push

# บนเซิร์ฟเวอร์ (ครั้งแรก git clone, ครั้งต่อไป git pull)
cd /var/www/student01 && git pull

ถ้า Deploy ด้วย Git ต้องกันไม่ให้คนเปิด /.git/ ผ่านเว็บได้ (ในนั้นมีประวัติโค้ดทั้งหมด) — เพิ่ม location ~ /\.git { deny all; } ใน Nginx

/etc/nginx/sites-available/student01
server {
    listen 80;
    server_name student01.example.ac.th;
    root /var/www/student01;
    index index.html index.php;

    location / {
        try_files $uri $uri/ =404;            # เว็บ HTML/CSS ที่เขียนเอง
        # try_files $uri $uri/ /index.php?$args;  ← ใช้บรรทัดนี้แทนถ้าเป็น WordPress
    }

    # เปิดใช้เฉพาะเว็บที่มี PHP / WordPress (ดูชื่อไฟล์ sock ด้วย: ls /run/php/)
    # location ~ \.php$ {
    #     include snippets/fastcgi-php.conf;
    #     fastcgi_pass unix:/run/php/php8.3-fpm.sock;
    # }

    location ~ /\. { deny all; }                 # ซ่อนไฟล์ .git .env
}
เปิดใช้งาน (ต้องใช้ sudo)
sudo ln -s /etc/nginx/sites-available/student01 /etc/nginx/sites-enabled/
sudo nginx -t                  # ต้องขึ้น "syntax is ok" และ "test is successful"
sudo systemctl reload nginx    # reload ไม่ตัดผู้ใช้คนอื่นที่กำลังเข้าเว็บ (ต่างจาก restart)

Virtual hosting: นักเรียนทั้งห้องใช้เซิร์ฟเวอร์ IP เดียวกันได้ เพราะเบราว์เซอร์ส่ง Host: student01.… มาใน HTTP Header ทุกครั้ง (Day 1!) Nginx จึงรู้ว่าต้องเปิดโฟลเดอร์ไหน

ใช้ Apache แทน Nginx? หลักการเดียวกัน: ไฟล์ /etc/apache2/sites-available/student01.conf ใช้ <VirtualHost *:80> + ServerName + DocumentRoot แล้ว a2ensite และ systemctl reload apache2

Docker (ทางเลือกสมัยใหม่): รันเว็บ Static ใน container เดียว docker run -d --name web01 -p 8081:80 -v /var/www/student01:/usr/share/nginx/html:ro nginx แล้วให้ Nginx ตัวหลักทำ proxy_pass http://127.0.0.1:8081; — แยกเว็บแต่ละคนออกจากกันได้ชัดเจน

เปิดเว็บแล้วเจอ “Welcome to nginx!” = server_name ไม่ตรง/ยังไม่ reload · เจอ 403 = สิทธิ์ไฟล์หรือไม่มี index.html · เจอ 502 = PHP-FPM ไม่ทำงาน — ดูสาเหตุจริงที่ /var/log/nginx/error.log

HTTPS ฟรีด้วย Let's Encrypt (certbot)

พิสูจน์ว่าเราเป็นเจ้าของโดเมนจริง แล้วรับใบรับรองอัตโนมัติ

ติดตั้งและขอใบรับรอง
sudo apt install -y certbot python3-certbot-nginx      # ครั้งเดียวต่อเซิร์ฟเวอร์
sudo certbot --nginx -d student01.example.ac.th      # เลือก Redirect เมื่อถูกถาม
sudo certbot renew --dry-run                            # ทดสอบการต่ออายุอัตโนมัติ
sudo certbot certificates                               # ดูใบรับรองทั้งหมดและวันหมดอายุ

ตรวจคุณภาพ HTTPS ที่ ssllabs.com/ssltest — ตั้งค่าดีจะได้เกรด A · และตรวจ Header ความปลอดภัยที่ securityheaders.com

อยากได้ใบรับรองแบบ Wildcard (*.domain) ต้องใช้วิธี DNS-01 challenge (ใส่ TXT record แทนการวางไฟล์) — ครูทำครั้งเดียวใช้ได้กับทุกซับโดเมนของนักเรียน

Let's Encrypt มี Rate limit (จำนวนครั้งที่ขอได้ต่อสัปดาห์) — ถ้าทดลองหลายรอบให้ใช้ --dry-run หรือ --staging ก่อน อย่ากดขอซ้ำ ๆ
